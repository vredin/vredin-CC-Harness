## Diablo gates passed (DA verdicts during integration)

1. **Plugin integration plan (initial)** — verdict: FIX FIRST. F1 (OSINT_project ambiguity), F2 (settings.json overwrite risk), F3 (no BACKUP commits), F4 (config-protection hook). All closed before any disk write.
2. **`/deploy` migration to template** — verdict: PROCEED WITH CAUTION. F5 (hardcodes in OSINT version), S9 (env.bak leak), S10 (fragile verify-live), S11 (no auto-rollback), S12 (E2E required). F5 + S9-S12 fixed in vendored version.

## SERIOUS findings closures

| ID | Closure |
|---|---|
| S1 (SSOT violation from vendoring) | Each vendored file carries comment with vendor SHA + URL. This migration file is the single source of truth for "what came from where". |
| S2 (Python hook performance ~130ms) | Bash case filter wraps Python invocation. Non-code files (.md/.json/.txt) skip Python entirely (~5ms). |
| S3 (comment-analyzer in template = dead weight per "no comments" rule) | NOT vendored to template default. Per-project opt-in for `CV_creator` and `Misko_parsing` only. |
| S4 (/ui-explore Diablo cost 3× per invocation) | Single Diablo pass compares all 3 mockups, not 3 separate calls. `--quick` mode for low-stakes UI. |
| S5 (Confidence scoring rubric needed) | `docs/rules-references/confidence-rubric.md` authored. Orchestrator scores, not the finding's owner. |
| S6 (Runtime deps not documented) | Pre-flight checks in scripts. Documentation in this file. STACK.md `deploy_runtime` field. |
| S7 (Atomic rollout = 5 simultaneous breakage risk) | Staged: template → Misko_parsing smoke test → AI-calendar/CV_creator/OSINT_project. |
| S8 (VERSION.json + migrations conventions unknown) | Read conventions from existing files. Followed: minor bump (3.0→3.1), migration file at `migrations/v3.0-to-v3.1.md`. |
| S9 (`.env.bak` leak after sed) | `/deploy` removes `.env.bak` after STEP 3 sed-injection. |
| S10 (Fragile grep verify-live) | `/deploy` uses `/health` endpoint + git_sha JSON field. Falls back to grep with warning if unconfigured. |
| S11 (No auto-rollback on post-migration failure) | `/deploy` `_rollback_if_needed` helper called on every ABORT after STEP 5. Auto-invokes `migration_downgrade` if set. |
| S12 (E2E required but not all projects have) | `/deploy` STEP 8.5 silently skips if `$e2e_dir` doesn't exist. |
| S13 (todo-diablo-gate behavior undocumented) | Explicit `comment` field in settings.json entry. Behavior fully described in this file. |
| S14 (context-budget-enforce env vars unclear) | Defaults explicit in settings.json `comment`. All 4 env vars documented with values. |
